# Ломалка эталонных примеров конфига платформы агентов

Генерирует `examples/06.. — 11../` — по одному внесённому дефекту на кейс,
из валидного `examples/05-конфиг-платформы-агентов/input/litellm-config.yaml`.
Каждый дефект — реалистичная ошибка: часть взята из слов Дениса Зорина на
интервью (`docs/interview-QZ5K.md`), часть — типовые классы багов, которые
руками почти не ловятся (кириллические омоглифы, тихие несовпадения типов).

Не зашита в конкретный файл Дениса — мутации ищут паттерны (regex) в любом
litellm-config.yaml похожей формы, `expected.md` собирается динамически из
того, что реально найдено и изменено. Можно скормить другой конфиг:

```bash
python3 tools/config-mutator/generate.py --config path/to/other.yaml --out-prefix 20
```

## Известное ограничение комнаты

`examples/05-конфиг-платформы-агентов/` — это `litellm-config.yaml` +
k8s `test-values.yaml`.

⚠️ **Поправка от 29.08.** Здесь стояло, что `tensorzero.toml` в примере 05
«нет вообще» и поэтому П2–П5 никогда не срабатывают на реальном входе.
Это неверно: TOML лежит **внутри** `test-values.yaml`, в `configMap.data`
(строка 82), и синтаксис, под который писаны правила, там настоящий —
8 вхождений `env::` и 8 секций `providers.`:

```bash
grep -n "tensorzero.toml" examples/05-конфиг-платформы-агентов/input/test-values.yaml
# 82:      tensorzero.toml: |

python3 -m core examples/05-конфиг-платформы-агентов --chat | grep -oE "\[П[0-9]+\]"
# [П1] [П2] [П3] [П5] [П12]
```

П2, П3 и П5 отрабатывают на боевом конфиге Дениса и находят там
чужой ключ у яндекса, неиспользуемую модель openrouter и ручной дрейф цен.
Ошибка возникла естественно: искали отдельный файл `.toml`, а он вложен
в k8s-манифест — глазами такое не видно.

Что из исходного наблюдения остаётся верным: правила действительно были
заточены под tensorzero-синтаксис, и **по семантике самого `litellm.yaml`
чекер долго не умел ничего** — ровно этот пробел и зафиксировали кейсы
06–11. Он закрыт правилами П7–П11 (PR #17): опечатка поля, омоглиф,
тип значения, дубль модели, выброс цены.
