# Ломалка эталонных примеров конфига платформы агентов

Генерирует `examples/06.. — 11../` — по одному внесённому дефекту на кейс,
из валидного `examples/05-конфиг-платформы-агентов/input/litellm-config.yaml`.
Каждый дефект — реалистичная ошибка: часть взята из слов Дениса Зорина на
интервью (`docs/interview-QZ5K.md`), часть — типовые классы багов, которые
руками почти не ловятся (кириллические омоглифы, тихие несовпадения типов).

Не зашита в конкретный файл Дениса — мутации ищут паттерны (regex) в любом
litellm-config.yaml похожей формы, `expected.md` собирается динамически из
того, что реально найдено и изменено. Можно скормить другой конфиг:

```bash
python3 tools/config-mutator/generate.py --config path/to/other.yaml --out-prefix 20
```

## Прогон против существующего чекера (`checkers/agent_platform_config/`)

На момент генерации (после PR #6, `alexfrmn`) чекер ловит **1 из 6** внесённых
дефектов:

| Кейс | Дефект | Ловит чекер? |
|---|---|---|
| 06 | опечатка в поле `custom_llm_provider` | ✗ |
| 07 | кириллический омоглиф в `model_name` | ✗ |
| 08 | секрет открытым текстом | ✓ (П1) |
| 09 | `timeout` строкой вместо числа | ✗ |
| 10 | дублирующийся `model_name` | ✗ |
| 11 | цена завышена в 1000 раз | ✗ |

08 — контрольный кейс: если он вдруг перестанет ловиться, значит регрессия
в самом чекере, а не в тестовых данных. Остальные пять — реальный пробел
чекера, зафиксированный этими кейсами как задача на доработку, а не баг
ломалки: чекер сейчас работает по regex-правилам П1–П6 (в основном заточен
под tensorzero.toml-синтаксис), а не по семантике litellm.yaml.

## Известное ограничение комнаты

`examples/05-конфиг-платформы-агентов/` — это `litellm-config.yaml` +
k8s `test-values.yaml`. Правила чекера П1–П5 писаны под формат
`tensorzero.toml` (`env::KEY`, `[models.X.providers.Y]`) — такого файла в
примере 05 нет вообще, поэтому П2–П5 сейчас никогда не срабатывают на
реальном входе. Это не относится к задаче ломалки напрямую, но стоит
на виду у комнаты при доработке чекера.
