# Как подключить свой модуль за минуту

Ядро уже умеет: читать вход примера, находить модули, собирать общий отчёт,
гонять всю приёмку. От тебя — одна папка с одним файлом.

## 1. Создай папку и файл

```
checkers/<твой-модуль>/checker.py
```

Обезличиватель по плану живёт отдельно — `anonymizer/checker.py`. Ядро смотрит
в обе стороны, регистрировать нигде ничего не надо: **общего списка модулей нет
намеренно**, он был бы единственным файлом, который правят все сразу.

## 2. Напиши два метода

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parent.parent.parent))
from core.model import Finding, Report

NAME = "config_rules"          # как тебя звать в отчёте

def matches(inputs: dict[str, str]) -> bool:
    """Мой ли это вход? Смотрим на имена файлов, не на содержимое."""
    return "app.env" in {Path(n).name for n in inputs}

def check(inputs: dict[str, str]) -> Report:
    """inputs: {имя файла: содержимое}. Вернуть Report."""
    report = Report()
    report.findings.append(Finding(
        rule_id="правило 3",
        rule_text="DEBUG выключен",
        where="app.env:4",
        quote="DEBUG=true",
        what="DEBUG включён в конфиге",
    ))
    report.notes.append("API_TOKEN_FILE — ссылка на файл вне репо, правило 1 соблюдено")
    return report
```

`matches` можно не писать вообще — тогда модуль берётся за любой вход.

## 3. Проверь себя

```bash
python3 -m core examples/02-конфиг     # свой пример, подробный отчёт
python3 -m runner                      # вся приёмка: «прошло N из 4»
python3 -m runner --verbose            # то же плюс полные отчёты
```

## Что важно знать про поля

| Поле | Зачем | Пример |
|---|---|---|
| `rule_id` | пункт чеклиста заказчика, дословно | `"п.3"`, `"правило 1"` |
| `rule_text` | сам текст правила | `"DEBUG выключен"` |
| `where` | точное место | `"spec.md:3"`, `"вал-102 · диаметр_мм"` |
| `quote` | цитата из артефакта | `"DEBUG=true"` |
| `what` | что не так, одной фразой | `"DEBUG включён в конфиге"` |
| `severity` | `"нарушение"` или `"вопрос"` | по умолчанию нарушение |

**`where` и `quote` заполняем всегда.** Заказчик должен пойти править, не
переспрашивая: без адреса и цитаты строка отчёта бесполезна.

**`notes` — то, что проверил и признал нормой.** Это не украшение: в примерах
02 и 03 половина приёмки именно про отсутствие ложных срабатываний
(`API_TOKEN_FILE` не секрет, толщина 11.96 при допуске −0.05 не брак).
Модуль, который ловит лишнее, проваливает пример так же, как модуль,
который не ловит ничего.

## Две вещи, которые ядро делает за тебя

1. **Пустой отчёт без единого отработавшего модуля показывается как
   `НЕ ПРОВЕРЕНО`, а не «соответствует».** Зелёный статус, которого никто
   не проверял, опаснее красного.
2. **Упавший модуль не роняет прогон** — ядро печатает предупреждение
   и идёт дальше по остальным.
