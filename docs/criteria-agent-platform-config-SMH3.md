# Критерии проверки конфига платформы агентов

Заказчик: Денис Зорин (QZ5K/SMH3). Задача дня: предпроверка конфига до
выкатки в тест — не проверка на самой тестовой среде.

Пропущенное нарушение хуже ложного срабатывания — при сомнении инструмент
предупреждает, а не молчит. Итог — статус: **OK** (можно катить) или список
нарушений с привязкой к правилу и месту в файле. Решило = ловит весь список
ниже, не только пункт про секреты.

## A. Секреты и переменные (жёсткая проверка)

1. Каждая ссылка на секрет (`os.environ/VAR`, `env::VAR`) соответствует
   переменной, реально объявленной в списке секретов деплоя
   (`additionalEnv.keys[].name`).
2. Секретов в буквальном виде в файле быть не должно.

## B. Согласованность провайдеров и функций

3. `functions.*.variants.*.model` ссылается на модель, реально объявленную
   в `[models.*]`/`[embedding_models.*]`.
4. `candidate_variants`/`fallback_variants` ссылаются только на варианты,
   реально объявленные в той же функции.
5. У каждой модели с `routing = [...]` есть соответствующая секция
   `[models.X.providers.Y]` для каждого провайдера из списка.
6. Нет полей, не входящих в ожидаемую схему провайдера (лишний/неиспользуемый
   параметр — как в прошлом инциденте).

## C. Цены

7. Поле `cost`/`input_cost_per_second` присутствует и не пустое.
8. Автосверка с источником: подтянуть актуальную цену с публичной страницы/
   документации провайдера; для рублёвых провайдеров конвертировать по курсу
   ЦБ РФ (cbr.ru); сравнить с ценой в конфиге. Расхождение **> 5%** —
   нарушение, ≤ 5% — норма (дрейф).

## D. Курс доллара

9. Если конвертация ₽↔$ захардкожена в нескольких местах файла — курс
   должен совпадать между ними.

## E. Синтаксис и обязательные поля

10. Файл валиден как YAML/TOML.
11. У каждого провайдера — обязательные поля (`type`, `api_base`,
    `model_name`, `api_key_location`, `timeouts`).

---

Вне scope (не проверяем в задаче дня): существование ключа в облаке,
диагностика ошибок рантайма, фактический запуск на тестовой среде.
