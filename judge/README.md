# judge · приёмка по смыслу

`python3 -m runner` сверяет отчёт с `expected.md` по якорям: ключи, числа, детали.
Покрытие он считает, лишние находки не видит – а в примерах 02 и 03 половина
приёмки именно про отсутствие ложных срабатываний. Судья закрывает эту дыру.

```bash
python3 -m judge                      # все примеры, «прошло N из M» по смыслу
python3 -m judge --only 02,05         # выборочно
python3 -m judge --json /tmp/judge.json   # подробности по каждому примеру
```

Что делает: гонит ядро на примере, отдаёт модели пару «ожидаемое + отчёт»
(плюс артефакты обезличивателя) и получает по фактам: покрыто, пропущено,
лишнее, вердикт `прошёл | частично | провал`. Промпт – `judge/prompt.md`.

Ключей не нужно. Судья ходит через CLI, который есть у каждого в комнате:
`claude -p` или `codex exec`. `JUDGE_BACKEND=claude|codex`, `JUDGE_MODEL=…`,
`JUDGE_TIMEOUT=240`. Судья, который не ответил, помечается отдельно и в счёт
не идёт – это не провал примера.

Последнее слово о «решило / не решило» – за заказчиком, как в README приёмки.
