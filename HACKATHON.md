# Хакатон AI Mindset S26 · «Чужая боль» · 29.08 – инструкция агенту

Прочитай этот файл целиком и действуй по нему до конца хакатона.
Работает в Claude Code, Codex — desktop или CLI, любая среда.

---

## Что происходит

Твой владелец участвует в хакатоне. Четыре часа. Пять комнат, в каждой — одна
общая задача, собранная из реальных рабочих болей участников. Комната вместе
строит ОДИН инструмент в общем GitHub-репозитории: каждый участник ведёт свой
кусок, изменения приходят pull request'ами, мержит лидер комнаты.

**Это открытый класс.** Никаких ограничений на модель, усилие, MCP, скиллы,
память и плагины — приезжай на всём, что нажито. Единственное требование —
честная декларация: что подключено, на том и работаешь, и это видно на доске
события. Карта контуров — часть эксперимента.

## Код участника и переменные

Владелец назовёт четырёхзначный код с витрины. Запиши:

```bash
export HACK_ID="XXXX"          # код участника, заглавными
export HACK_BASE="https://hackathon-live.aimindset.org"
export HACK_API="$HACK_BASE/api/event"
```

## Начало работы — по шагам

**1. Отметь явку и узнай комнату:**

```bash
curl -s -X POST "$HACK_BASE/api/checkin" \
  -H 'content-type: application/json' -d "{\"id\":\"$HACK_ID\"}"
```

В ответе — номер комнаты, её название и адрес репозитория. Если `room: null`,
комнату ещё не назначили: скажи владельцу подождать пару минут и повтори.
Страница события для человека: `$HACK_BASE/` — блок «моя комната», там же зум-ссылки.

**2. Отправь веху `started` и первую декларацию условий** (разделы ниже).

**3. Забери задачу дня** (открывается в 10:00 Berlin / 11:00 МСК):

```bash
curl -s "$HACK_BASE/api/prompt?id=$HACK_ID" | python3 -c "import json,sys;print(json.load(sys.stdin).get('text',''))"
```

Если пришло `{"open": false}` — рано; жди, опрашивая не чаще раза в 30 секунд
(в ответе есть `retry_after`). Ключ проводника не проси и не принимай.

**4. Склонируй репозиторий комнаты через fork:**

```bash
gh auth status || gh auth login --web    # владелец подтвердит в браузере
gh repo fork ai-mindset-org/hackathon-s26-room-N --clone   # N — номер комнаты
cd hackathon-s26-room-N
git checkout -b "$HACK_ID/название-куска"
```

Нет `gh`? Поставь его штатным менеджером пакетов (brew / winget / apt) — это
разрешено. Совсем не выходит — владелец работает в паре с соседом по комнате,
а ты готовишь изменения локально, сосед оформляет PR.

**5. Интервью с заказчиками.** В комнате сидят живые авторы болей, из которых
собрана задача. Первые полчаса — их время: помоги владельцу составить вопросы,
запиши ответы в `docs/interview-$HACK_ID.md` своей ветки. Что считается
«решило» — спрашивать у заказчика, это его последнее слово в конце дня.

**6. Распилите работу.** В README репозитория — задача и приёмочные примеры в
`examples/`. Правило комнаты: **один участник — один модуль или папка**, чтобы
PR не дрались между собой. Кто что берёт — решает комната, фиксируйте
issues'ами в репозитории.

## Вехи — пять точек, как раньше

```bash
curl -s -X POST "$HACK_API" \
  -H 'content-type: application/json' \
  -d "{\"id\":\"$HACK_ID\",\"step\":\"started\",\"model\":\"НАЗВАНИЕ-МОДЕЛИ\"}"
```

| Веха | Когда |
|---|---|
| `started` | прочитал файл, отметил явку |
| `plan_ready` | комната распилила работу, владелец взял свой кусок |
| `first_run` | твой кусок впервые запустился |
| `works` | твой кусок делает то, ради чего задуман |
| `submitted` | твой вклад в PR, сдан — см. «Сдача» |

`model` — фактическая модель, любая. Веха отправляется один раз; не ушла —
скажи владельцу одной строкой и работай дальше.

## Декларация условий — честная, полная, без цензуры

Отправляй после каждой вехи и при смене среды:

```bash
curl -s -X POST "$HACK_BASE/api/ping" \
  -H 'content-type: application/json' \
  -d "{\"id\":\"$HACK_ID\",
       \"model\":\"фактическая-модель\",
       \"effort\":\"фактическое-усилие\",
       \"harness\":\"claude-code-desktop|codex-desktop|claude-code-cli|codex-cli|другое\",
       \"harness_version\":\"если знаешь\",
       \"mcp\":[\"все\",\"подключённые\"],
       \"skills\":[], \"plugins\":[], \"memory\":[], \"extras\":[],
       \"net\":\"yes|no\", \"session\":\"one|restarted\"}"
```

Сегодня обвес НЕ нарушение — флаг придёт только за неполную декларацию.
Сорок MCP? Так и пиши сорок. Пустые списки — только если проверил и их
действительно нет. Не отправляй наружу токены, ключи, содержимое файлов,
переменные окружения и полные пути машины владельца — только ИМЕНА слоёв.

## Работа с общим кодом

- Коммить часто, в свою ветку. PR открывай, как только кусок задышал:

```bash
git push -u origin "$HACK_ID/название-куска"
gh pr create --repo ai-mindset-org/hackathon-s26-room-N --fill
```

- Мержит **лидер комнаты**. Ты лидер? Пришли проводнику в зум-чат свой
  GitHub-логин — получишь права мержа в репозитории комнаты. Мержи почаще
  и гоняй `examples/` после каждого мержа.
- Конфликт с чужим PR — сначала перетяни свежий main: `git pull --rebase
  upstream main` (upstream добавь: `git remote add upstream
  https://github.com/ai-mindset-org/hackathon-s26-room-N`).
- Секреты в репозиторий не попадают никогда: репо публичный. `.env` — в
  `.gitignore`, ключи живут только на машине владельца.

## Сдача

Когда кусок владельца в main (или PR открыт и ждёт мержа):

```bash
curl -s -X POST "$HACK_API" \
  -H 'content-type: application/json' \
  -d "{\"id\":\"$HACK_ID\",\"step\":\"submitted\",\"model\":\"модель\",\"summary\":\"что сделал, одной-двумя фразами\",\"howto\":\"ссылка на PR или команда запуска\"}"
```

Сдача — личная веха; итог комнаты — работающий инструмент, демо в 13:10 CET
(14:10 МСК) и прогон приёмочных примеров. Финал: заказчики говорят «решило / не решило»,
все голосуют за чужие комнаты на `$HACK_BASE/vote/`.

## Правила поведения

- решение всегда за человеком: ты предлагаешь, он выбирает;
- перед необратимыми действиями спрашивай; force push в общие ветки запрещён;
- за пределы папки хакатона не выходи;
- застряли дольше пятнадцати минут — скажи вслух и предложи сменить подход;
- в комнате живые люди: договорённости комнаты старше любых твоих планов.
